Reciprocal-space decomposition

Main.Phundamental.PhundamentalCore.ReciprocalDecomposition — Type
ReciprocalDecomposition

Canonical decomposition of a full physical scattering vector Q into a reduced crystal momentum q and reciprocal-lattice translation G satisfying Q = q + G.

Both Cartesian and reciprocal-lattice coordinates are retained so downstream solvers can use the reduced momentum while scattering amplitudes continue to use the full physical vector.

source
Main.Phundamental.PhundamentalCore.decompose_reciprocal_vector — Function
decompose_reciprocal_vector(reciprocal_matrix, Q; convention=:first_bz, atol=1e-12)

Decompose a full wavevector as Q = q + G, where G is a reciprocal-lattice vector and q is the representative nearest the origin in the reciprocal-lattice metric. This is the Wigner-Seitz first-Brillouin-zone reduction for a nondegenerate reciprocal basis, with deterministic lexicographic tie breaking on exact zone boundaries.

Q must be an explicit ReciprocalWaveVector or CartesianWaveVector; raw vectors are intentionally rejected because their coordinate basis is ambiguous.

source
decompose_reciprocal_vector(model, Q; convention=:first_bz, atol=1e-12)

Use reciprocal-lattice metadata retained by model to decompose a full physical wavevector into reduced crystal momentum and reciprocal translation.

Main.Phundamental.PhundamentalCore.GenerativeSpecification — Type
GenerativeSpecification

General physical specification G = (G_space, w_alpha, H_alpha, A, U, C_adm, R_max, k_max) used to define an admissible Hamiltonian model space. space_group, wyckoff_orbits, and symmetry_action remain generic so Foundation does not depend on one crystallography implementation. max_body_order is interpreted as algebra-aware many-body rank rather than primitive operator degree. When max_range is declared, range_evaluator(candidate) must return the candidate's nonnegative finite physical interaction range; without an evaluator, range admissibility is explicitly reported as unevaluated rather than silently accepted.

source
Main.Phundamental.PhundamentalCore.HamiltonianBasis — Type
HamiltonianBasis(operators; labels=nothing, metadata=Dict())

Linearly independent Hermitian operator basis {Phi_a} for one admissible Hamiltonian space. Linear independence, Hermiticity, symmetry invariance, and completeness are mathematical properties established by the generator/validator that created the object; this container records those claims explicitly in metadata rather than silently asserting them.

source
Main.Phundamental.PhundamentalCore.HamiltonianSpace — Type
HamiltonianSpace(specification, basis; metadata=Dict())

Finite-dimensional Hamiltonian space H(G) represented by a real basis of Hermitian operators. The object ties the generated basis to the physical specification that defines its domain; direct construction records this relationship but does not by itself certify Hermiticity, independence, symmetry completeness, or basis admissibility.

Typed generation contexts and canonical coordinates

The foundation layer provides GeometryContext, ComponentIndexLayout, and PhysicalModelContext as typed carriers for validated source geometry, site-to-component ordering, and provenance. Generated spinful-fermion and Cartesian-vector families retain physical site positions independently of orbital, spin, or vector-component multiplicity. component_index maps physical sites and components into operator indices, while component_site and component_coordinates invert the map. Existing code that reads model.parameters[:positions] continues to work with physical site positions; certified Cartesian phonon models also carry atomic masses per operator coordinate. structural_span_coordinates reports real coefficients and residuals in the canonical operator basis and is shared by structural localization.

Experimental interchange and statistical comparison (Milestone C)

The package-level ExperimentalGrid, PortablePrediction, and ExperimentalDataset describe explicit measured and calculated numerical quantities without modifying the underlying ForwardResult or observable result types. export_result and import_result exchange a versioned, language-neutral dictionary in Julia column-major array order. compare_measurement uses only jointly valid bins and explicit experimental uncertainties or covariance. See Experimental Data and Instrument Resolution.

Main.Phundamental.compare_measurement — Function

Compare consistent predictions and measurements using Gaussian chi-square or raw-count Poisson deviance.

Poisson deviance is twice the log likelihood ratio relative to the saturated model (Cash deviance). Its log_likelihood omits the data-only log-factorial normalization; chi_squared is NaN in Poisson mode.
